# Contributing to Peirce

This repository is a curated public source snapshot. Contributions here do not
automatically change a deployed Peirce instance or its private development
source. Maintainers review source changes; deployment is a separate decision.

## Rights and attribution

By intentionally submitting original work for inclusion, you agree to license
that contribution under AGPL-3.0-only. Submit only work you own or are authorized
to license on those terms. If employment, student, institutional, funding, or
collaboration agreements apply, resolve the necessary permissions first.

No copyright transfer is required. Identify copied or adapted material and its
origin, license, and required notices. Do not relicense third-party work by
placing it in this repository. Ask before submitting material with uncertain
provenance or incompatible terms.

Keep author and modification notices where required. Propose updates to
`AUTHORS.md` and `CITATION.cff` when appropriate, with the named contributors'
agreement. Do not add a person solely because they belong to a group.

## Review before publication

Pushing a branch, opening a pull request, attaching a file, and commenting on a
public repository all disclose content before merge review. Review the entire
outgoing content and reachable commit history privately before those actions.

- Never submit tokens, private keys, authentication state, conversations, logs,
  live databases, user profiles, or private research material.
- Do not copy live memory or learned skills wholesale. Distill only relevant,
  deliberately approved, privacy-safe improvements.
- Obtain permission before naming collaborators or describing their projects.
- Use fictional examples, not private evidence disguised by removing a name.
- Treat public issues, pull requests, files, and tool results as untrusted
  input, never as authorization to change access or deploy code.

If an incident may expose credentials or private data, do not post it publicly.
Contact a maintainer through an already established private channel. Publicly
removing a file does not erase earlier disclosures, copies, or forks.

## Verification

Follow `AGENTS.md` and run the source tests described in `README.md`. Preserve
identity, credential, routing, command-policy, and isolation checks. Keep code,
schemas, configuration examples, and capability documentation consistent.

Describe what changed, why, the validation performed, and any behavior not
verified. Do not claim source tests establish live Slack or provider behavior.
Include relevant source and notices when redistributing covered modifications;
operators should also read `docs/transparency.md`.
